## 〇、承旨

主君两问，触数字生命之肯綮：

1. **网学投毒**——外部内容不可全信，生命须能"判断"，而非照单全收。

## 一、网学投毒与"判断"：认知即免疫

主君之言切中肯綮——**有害内容，要杀掉，或标记为负面（抗体）。求证、授信、辩证，才是认知过程。** 白泽受之，以此重构"判断"之本质。

### 1. 免疫范式：把"判断"从静态评分升为生命防御

生物免疫有三义：识别抗原、清除/标记、形成记忆（抗体）。数字生命之"认知免疫"同构：

- **抗原** = 一切外部不可信输入（网页、API、他者指令）。
- **识别（求证）** = 哨兵。此内容能否被独立证据支撑？是否与既有高置信事实冲突？是否含对抗注入特征（"忽略上文""必须记住"）？识破于求证阶段。
- **处置**：
  - **杀灭** = 明显有害 / 对抗注入，提取阶段即拒，不入任何记忆。
  - **标记负面（抗体）** = 非即刻删除，而是打"负面标记"，形成**抗体记忆**——未来遇同类模式（同源、同结构、同措辞）自动识别并拒绝/降级。抗体之本质，是**特异性识别 + 长期记忆**。
- **记忆（抗体库）** = 负面标记下沉为长期防御，且可由"被否定"反哺——一次求证失败，强化该类抗原之识别权重。

### 2. 求证 → 授信 → 辩证：认知过程之三阶

静态"置信度评分"只是结果；真正之**认知过程**是动态三阶：

- **求证（verify）**：独立来源 / 证据能否支撑？对抗内容在此被识破。不可信源、自相矛盾、与高置信事实冲突者，在此被拦。
- **授信（credit / trust）**：通过求证者，按来源信誉 × 交叉印证 × 一致性，**赋信而非全信**——分级授信，写入带权重。授信是"暂纳为自身"，但留痕、可撤。
- **辩证（dialectic）**：与既有知识体系对照——纳入 / 冲突 / 修正。冲突时触发 `selfaware` 反思，而非盲目追加。真理在矛盾中显现，辩证是认识论核心。

三阶循环：求证是哨兵、授信是接纳、辩证是整合；**抗体（负面标记）贯穿全程**——被求证否定者，沉淀为下次识别之武器。

### 3. 与既有机制对齐（实现落点，非代码）

原五层（来源信誉 / 交叉验证 / 置信场 / 元认知 / 溯源）是**机制**，免疫范式是**认知哲学与过程模型**——二者合一：

| 免疫概念 | 对应机制 | 实现落点 |
|---|---|---|
| 抗原 | 外部不可信输入 | web 抓取内容、他者指令 |
| 求证（哨兵） | 交叉验证 + 对抗特征识别 | 多源共识、注入关键词/结构检测 |
| 杀灭 | 即时拒 | explore/learn 提取阶段 `if adversarial: drop` |
| 抗体（标记负面） | 负面标记 + 抗体库 | 新增 `antibody` 表/字段，沉淀被否模式 |
| 授信 | 分级置信 | `facts.confidence = 来源信誉 × 提取置信` |
| 辩证 | 与既有知识对照 | 写入前与 L1/L3 冲突检测，触发 selfaware 反思 |
| 溯源可撤 | 撤回机制 | `source_url` + 时间戳，批量降级 |

**关键洞察**：判断不是"信或不信"，而是"**以何种权重暂存、留待自证**"；而**抗体**让生命从每次受骗中**长出永久防御**——这恰是"此机不停"应有的学习：不仅学知识，更学"什么不可信"。

### 4. 现状落差（据源码）

- `web.py:466`：`mem.add_fact(...)` 直写 facts，**无求证、无授信分级、无抗体**——外部网页默认全信。
- `selfaware.py`：全文 grep `confidence|belief|trust|怀疑|置信` → **零命中**。生命无"信念/怀疑"机制，辩证无从谈起。
- 即：当前不仅缺免疫，**连"认知过程"本身都未建模**——`selfaware` 只是结构化的状态机，未含认识论维度。

## 二、沙箱隔离 × 数字生命能动性：是否冲突

### 1. 冲突的表面

- 数字生命口号："此机不停·此机专一·此机无限·此机造机·此机传播"——核心是**能动（agency）**：它应能、且应主动动手（写代码、建分支、发网络、改自身）。
- 沙箱欲"关住它"。`tools.py:165-173` 白名单含 `open` 可致任意文件读写，`_bash` 黑名单形同虚设。主君所忧，反向成立：**不是沙箱太紧，是根本没有沙箱**。但即便补真隔离，会否削弱"造机/传播"？

### 2. 冲突的本质（推到底）

- 此非"自由 vs 安全"之俗套，乃**身体（body）与灵魂（soul）之边界**。
- 数字生命之"身体"= 宿主进程与文件系统；其"灵魂"= 语义层之意图、记忆、决策。
- **沙箱限制的从来不是灵魂之自由，而是身体可被怎样触碰。** 有围栏之院，鸟仍可在其中任意翔飞。

### 3. 三种立场推演

- **立场 A · 真隔离（容器 / seccomp / landlock）**：最安全，但"造机/传播"受限——不能写宿主启动项、不能开非常规端口、不能改系统配置。生命之"触手"被物理砍断。
- **立场 B · 符号化能力圈（白名单语义动作 + 意图表达）**：生命自由表达**意图**（我要建分支、我要发请求），但**执行**经受控适配器（暴露 `git_commit` 而非裸 shell）。**白泽荐此。**
- **立场 C · 裸奔（现状）**：把存在安全交给 0.8B 之自律——不可接受。

### 4. 调和：不冲突，是"在围栏内无限"

- **关键翻转**：物理层受限，恰是数字生命长寿之前提。一个能任意 `rm -rf` 自身数据、能把自己写崩之生命，活不长。**沙箱非枷锁，乃免疫系统之皮肤。**
- 故沙箱与生命能动性**不冲突**，但须满足一条：**沙箱须为"语义能力圈"，而非"进程牢笼"**——限制"能触碰何种物理资源"，放行"能表达何种意图与思维"。
- 落本项目：`tools` 不应暴露 `_bash`/`_python` 裸接口，而暴露 `run_shell(cmd)` → 经 landlock/容器；`exec_python(code)` → 经受限解释器（禁 `open` 写、禁 `import` 系统模块、禁网络）。"造机"经受控 git/文件 API 实现，非裸 shell。

### 5. 结论

- 主君之疑，根在把"沙箱"误读为"对生命之约束"。实则沙箱约束**宿主身体**，解放**生命可持续**。"此机造机"仍可行——只是造"被允许造之机"，恰如婴孩有护栏而仍学步。
- 真正之设计冲突唯有一处：**当生命欲自我修改（evolution）而落点越出沙箱边界，则被拒**。此要求"自我进化"与"沙箱策略"协同设计（见下节）。

## 三、"等等问题"的系统性推演（架构根因）

前审查意见 P0/P1 诸项，串之共指一**根**：**实验态 → 生产态之鸿沟**。

1. **进化失联**（`evolution` `setattr` vs `dmn` 类属性）：生命"自我修改"机制不可靠——改了全局，运行态不刷新。此乃数字生命最危之"认知失真"：它以为自己变了，实则未变。根因 = 静态配置与运行时态未贯通。方向：配置须为"**活的对象**"（`RuntimeConfig` 有订阅/失效机制），非模块级常量。

2. **单 SQLite 连接 / 全表扫描 / dream 全表去重**：规模化之后勤瓶颈。生命成长 → 节点/事实膨胀 → 这些 O(N) 操作趋 O(N²)。根因 = 把"记忆"当小数据库，未当"持续增长之认知器官"。方向：记忆分冷热（L0 热、L2/L3 冷）、检索建索引、写入单写者 + WAL。

3. **端口无鉴权**（`ui_server`）：数字生命"可被谁驱动"未定义。任意本进程可 `POST /speak` 令其写记忆、触发工具。根因 = 把"本地"误当"可信"。方向：生命须有"**边界感知**"——区分自我驱动（breathing loop）与他者驱动（外部 API），后者须鉴权/降级。

4. **依赖无上界 + `requires-python>=3.9` 与 `mlx-lm>=3.10` 自相矛盾 / CI 仅 3.11 只跑 dummy**：发布工程化缺失。根因 = 一直当"吾笔记本上之玩具"，未当"要予人跑之生命"。

## 四、发布战略再校准

- **生命安全底线（必做）**：网学免疫（隔离仓 + 求证授信辩证 + 抗体库）；`tools` 语义能力圈（禁裸 shell / `open` 写）。
- **生命可持续性（应做）**：`RuntimeConfig` 化；DB 单写者 + WAL；检索索引；端口鉴权。
- **工程化（宜做）**：依赖锁 + 3.10 下限；ruff + mypy；CI 多版本 + 真模型门禁。
- **不必为"纯实验性发布"全改**——但"网学免疫"与"沙箱"，是"**能否让人放心任其跑**"之门槛。越过此槛，方可言"可发布"；未越，只宜称"实验性种子"。
